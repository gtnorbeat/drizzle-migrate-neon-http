# 2026-08-19

## drizzle-migrate-neon-http — release 0.2.0 + docs/branding

### 1. Release 0.2.0 (shipped)

Operational hardening, driven by real CI usage:

- **New CLI flags / API options** — `--strict`, `--retries <n>`,
  `--timeout <ms>` (API: `strict`, `retries`, `timeoutMs`).
- **Orphaned-migration detection** — `.sql` files present on disk but missing
  from `meta/_journal.json` were silently skipped before; they now warn by
  default and hard-fail under `--strict` (the "column does not exist" failure
  mode this prevents).
- **Logger fix** — idempotent-skip messages now route through the injected
  `log` instead of `console.log`.
- 48 unit tests; coverage 100% lines / 98% branches on `src/**`.

Flow: `agent/hardening-0.2.0` → PR #21 → `main`, tag `v0.2.0`. E2E on Neon and
the full test matrix passed on the tag.

### 2. npm publish — new browser/passkey auth

- npm is restricting tokens that bypass 2FA for direct publishing. The CI
  `NPM_TOKEN` started returning `404` on the publish PUT (which is why
  `0.1.10` never reached npm — `0.1.9` was the last CI-published version).
- `0.2.0` was published via the interactive web-auth flow: `npm publish` under
  a pty → browser opens (`DISPLAY=:0`) → passkey → publish completes.
- **Follow-up**: the publish workflow still uses `NPM_TOKEN`; it needs a new
  auth approach (OIDC/provenance or per-release browser auth) before the next
  release, or future CI publishes will fail the same way.
